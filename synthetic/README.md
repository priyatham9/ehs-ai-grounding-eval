# SYNTHETIC DATA — NOT EXPERIMENTAL RESULTS

Everything in this directory is machine-generated by a simulation. **No file here
describes the behaviour of any real AI system.** Nothing here may be cited as a
finding, quoted as a measurement, or used to support any claim about grounding,
retrieval, or hallucination.

## What is in here

`generate_demo_run.py` runs the mock adapter over the real question corpus and
writes the resulting run files to `demo_run/`. Those run files show what the
harness produces and what the report format looks like. That is their entire
purpose.

## Why the numbers in `demo_run/` are meaningless

`MockAdapter` composes its answers **out of the corpus item it is answering**. Its
correct responses are built from the item's own reference answer. Its wrong
responses are built from the item's own adjacent-wrong description. Whether it
answers correctly on a given item is decided by a seeded coin flip against a fixed
profile probability.

It therefore scores, by construction, almost exactly as well as its profile says
it will. Reading "the grounded arm reached about 80 percent accuracy" off
`demo_run/` is reading back the constant `p_correct = 0.80` that was typed into
the `grounded` profile definition in `grounding_eval/adapters/mock.py`. It is not
a measurement of anything.

The three profiles (`ungrounded`, `pseudo_grounded`, `grounded`) have
probabilities chosen so that the harness exercises every scoring branch and so the
report has something to display. They are **inputs to a simulation**, not estimates
of how any real system behaves.

## Labelling

Every response the mock adapter produces carries the provenance string
`MOCK_DEMONSTRATION_FIXTURE_NOT_RESULTS`. Every run file it writes records
`"is_mock_demonstration": true` and is named with a `mock__` prefix. Any attempt to
render a summary of a mock run with the banner suppressed raises an exception
rather than printing quietly, and renaming the adapter does not remove the label,
because the flag is read from the responses rather than from the adapter's
self-reported name.

The test suite asserts all of this.

## What is NOT synthetic

The question corpus in `corpus/` is not synthetic. Its questions, reference
answers and clause citations are drawn from public federal regulations and are
verified against the eCFR; see `corpus/verification/source_verification.json`.

## Regenerating

```bash
python3 synthetic/generate_demo_run.py
```

The scored content — every response, outcome and score — is deterministic given
the seed recorded in each run file. The files are not byte-identical across
regenerations, because each run also records wall-clock fields (`started_utc`,
`duration_s`, and a per-response `latency_s`). Compare runs with those fields
stripped.
